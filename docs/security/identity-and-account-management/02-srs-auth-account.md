# 02. Software Requirements Specification (SRS): Auth & Account Management

This document defines formal Functional Requirements (FR), Non-Functional Requirements (NFR), and Security Invariants (SEC) with verifiable acceptance criteria, priorities, and traceable standard references.

---

## 1. Functional Requirements (FR)

### 1.1 Registration & Onboarding

| ID              | Title & Description                                                                                                                                                                             | Priority | Traceability / Ref                             | Acceptance Criteria                                                                                                                                                                                                                                                                                                                          |
| :-------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------- | :--------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **FR-AUTH-001** | **Direct Registration Without Email Verification**<br/>The system shall register a user using an email address and a password without requiring email confirmation, OTP, or verification links. | **MVP**  | NIST SP 800-63B-4<br/>OWASP Auth Cheat Sheet   | 1. Upon submitting valid credentials, the account is created with `status: active` immediately.<br/>2. No verification email or token is generated or dispatched.<br/>3. The API response returns a valid authenticated session or standard 201 Created payload.<br/>4. The user can immediately authenticate without any intermediary gate. |
| **FR-AUTH-002** | **Registration Anti-Enumeration**<br/>The registration API must not disclose whether an email address is already registered in a manner that assists account harvesting.                        | **MVP**  | OWASP Auth Cheat Sheet<br/>OWASP REST Security | 1. If an email already exists, the server returns an identical generic error format or status code that matches generic validation failures, or initiates a defensive flow without exposing user existence.<br/>2. Response time must be normalized to prevent timing-based side-channel enumeration.                                        |
| **FR-AUTH-003** | **Unverified Email Notification in UI**<br/>The UI shall prominently inform the user that their email is self-asserted and unverified.                                                          | **MVP**  | Product Policy<br/>OWASP Abuse Case            | 1. Registration UI provides an explicit warning to double-check spelling.<br/>2. Profile displays an _"Unverified / Self-Asserted"_ status badge next to the email.<br/>3. The email is never badged as "Verified" or "Trusted".                                                                                                             |

### 1.2 Authentication & Session Management

| ID              | Title & Description                                                                                                                           | Priority | Traceability / Ref                        | Acceptance Criteria                                                                                                                                                                                                                                                                      |
| :-------------- | :-------------------------------------------------------------------------------------------------------------------------------------------- | :------- | :---------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **FR-AUTH-004** | **Credential-Based Login**<br/>The system shall authenticate users via valid email and password credentials.                                  | **MVP**  | NIST SP 800-63B-4<br/>OWASP Session Mgmt  | 1. Valid credentials produce a new active session with rotated session identifier.<br/>2. Invalid credentials return HTTP 401 with generic error: `"Invalid email or password"`.<br/>3. No distinction is made between nonexistent account and incorrect password.                       |
| **FR-AUTH-005** | **Single-Device Logout**<br/>The user shall be able to terminate the current session on the active device.                                    | **MVP**  | OWASP Session Mgmt                        | 1. Calling logout immediately marks the current session as revoked in the database/cache.<br/>2. Associated browser cookies (`sid`) are expired with `Max-Age: 0`.<br/>3. Subsequent requests with the revoked session return HTTP 401 Unauthorized.                                     |
| **FR-AUTH-006** | **Global Logout (Revoke All Devices)**<br/>The user shall be able to terminate all active sessions across all devices simultaneously.         | **MVP**  | OWASP Session Mgmt                        | 1. All active sessions associated with the user ID are marked revoked.<br/>2. Both Web and Electron desktop clients are forced to re-authenticate on next API call.<br/>3. Audit log records `AUTH_SESSION_ALL_REVOKED`.                                                                 |
| **FR-AUTH-007** | **Active Session Listing & Remote Revocation**<br/>The user shall be able to view all active sessions and revoke any specific remote session. | **MVP**  | ASVS v4.0.3 (V3.3)<br/>OWASP Session Mgmt | 1. Session list displays client type (`Web` or `Desktop`), approximate location (derived from IP prefix), and last active timestamp.<br/>2. Current session is clearly highlighted.<br/>3. Revoking a remote session invalidates it immediately without terminating the current session. |

### 1.3 Account Recovery

| ID              | Title & Description                                                                                                                                       | Priority | Traceability / Ref                               | Acceptance Criteria                                                                                                                                                                                                                                                                                                          |
| :-------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- | :------- | :----------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **FR-ACCT-001** | **Password Reset Request (Forgot Password)**<br/>The system shall issue a single-use, time-limited reset link to the recorded contact email upon request. | **MVP**  | OWASP Forgot Password<br/>NIST SP 800-63B-4      | 1. The API always responds with HTTP 200: `"If the email matches an account, a reset link has been dispatched"`, regardless of account existence.<br/>2. Reset token is cryptographically random (>= 128-bit entropy) with maximum 15-minute TTL.<br/>3. Only the SHA-256 hash of the reset token is stored in the database. |
| **FR-ACCT-002** | **Password Reset Execution**<br/>The user shall set a new password using a valid, unexpired reset token.                                                  | **MVP**  | OWASP Forgot Password<br/>OWASP Password Storage | 1. Submitting a valid token updates the user's password hash using Argon2id.<br/>2. The reset token is marked as `used_at` and cannot be reused.<br/>3. All existing active sessions for that user are immediately revoked.<br/>4. Submitting an expired or reused token returns HTTP 400 Bad Request.                       |

### 1.4 Profile & Account Management

| ID              | Title & Description                                                                                                                        | Priority | Traceability / Ref                           | Acceptance Criteria                                                                                                                                                                                                                                                            |
| :-------------- | :----------------------------------------------------------------------------------------------------------------------------------------- | :------- | :------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **FR-ACCT-003** | **View & Update User Profile**<br/>The user shall view and update non-security profile attributes (display name, avatar URL, preferences). | **MVP**  | OWASP REST Security                          | 1. Modifying profile updates the database and reflects immediately in the UI.<br/>2. Inputs are strictly validated against character length and XSS patterns.                                                                                                                  |
| **FR-ACCT-004** | **Self-Service Password Change**<br/>The user shall update their password from the account security settings.                              | **MVP**  | NIST SP 800-63B-4<br/>OWASP Auth Cheat Sheet | 1. The operation requires entering the current password (re-authentication).<br/>2. Upon success, all other sessions are revoked, or the user is given an explicit option to revoke other sessions.<br/>3. New password must meet NIST length requirements (>= 15 characters). |
| **FR-ACCT-005** | **Self-Service Account Deletion**<br/>The user shall be able to permanently delete their account.                                          | **MVP**  | GDPR Art. 17<br/>OWASP ASVS                  | 1. Deletion requires re-entering the current password.<br/>2. Account status is set to `deactivated` or deleted; all sessions, stored API keys, and credentials are hard purged or cascade-deleted.<br/>3. Audit log records account deletion with user ID pseudonymized.      |

### 1.5 Third-Party AI Provider API Keys Vault

| ID              | Title & Description                                                                                                                          | Priority | Traceability / Ref | Acceptance Criteria                                                                                                                                                                                                                                                                                                    |
| :-------------- | :------------------------------------------------------------------------------------------------------------------------------------------- | :------- | :----------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **FR-SECR-001** | **User-Provided AI API Keys Storage**<br/>The user may store API keys for external AI providers (Gemini, OpenAI) to execute model inference. | **MVP**  | OWASP Secrets Mgmt | 1. Keys are submitted over HTTPS directly to the backend vault API.<br/>2. Keys are encrypted at rest using AES-256-GCM via envelope encryption.<br/>3. Keys are never returned in plaintext in any GET request; UI displays only masked hint (e.g., `sk-...4a2f`).<br/>4. User can update or delete keys at any time. |

## 2. Non-Functional Requirements (NFR)

| ID                | Category      | Metric / Specification                                      | Target Threshold                                                                                                              | Validation Method                           |
| :---------------- | :------------ | :---------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------ |
| **NFR-PERF-001**  | Performance   | Authentication API latency (p95) under nominal load.        | `< 300ms` (inclusive of Argon2id hashing overhead).                                                                           | Automated Load Testing (k6).                |
| **NFR-PERF-002**  | Throughput    | Distributed session validation latency via Redis.           | `< 15ms` (p99).                                                                                                               | Benchmarking cache lookups.                 |
| **NFR-AVAIL-001** | Availability  | Uptime of the Auth & Session API service.                   | `99.9%` monthly uptime.                                                                                                       | Health check probes & synthetic monitoring. |
| **NFR-PRIV-001**  | Privacy       | IP address retention and PII redaction.                     | Zero full IP addresses in application logs; IP truncated to `/24` (IPv4) or `/48` (IPv6) in audit records.                    | Automated log compliance scanning.          |
| **NFR-A11Y-001**  | Accessibility | Web & Electron auth forms meet WCAG 2.1 Level AA standards. | 100% keyboard navigable; form inputs have explicit labels, error announcements via ARIA live regions, minimum 4.5:1 contrast. | Axe-core automated tests & manual review.   |

## 3. Security Invariants (SEC)

| ID               | Domain                    | Rule / Constraint                                                                                                                                                                                | Enforced Mechanism                                                                     | Reference                                                 |
| :--------------- | :------------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------- | :-------------------------------------------------------- |
| **SEC-PWD-001**  | Password Policy           | Minimum length: 15 characters (single-factor). Maximum length: 128 characters. Allow all unicode characters, paste, and password managers. Zero composition rules.                               | Enforced at client and server schema validation.                                       | NIST SP 800-63B-4 (Section 5.1.1.2)                       |
| **SEC-PWD-002**  | Password Storage          | Hash with Argon2id: memory cost `m = 64MB` (65536 KiB), time cost `t = 3` iterations, parallelism `p = 4`, 16-byte cryptographically secure random salt.                                         | Cryptographic hashing library (e.g., `@node-rs/argon2` or native sodium).              | OWASP Password Storage Cheat Sheet                        |
| **SEC-SESS-001** | Web Session Storage       | Session cookies must enforce `HttpOnly; Secure; SameSite=Lax`. Session tokens must NEVER be stored in `localStorage` or `sessionStorage`.                                                        | Web application server cookie generator and client-side code review.                   | RFC 10017<br/>OWASP Session Mgmt                          |
| **SEC-SESS-002** | Session Lifecycle         | Idle session timeout: 24 hours. Absolute session timeout: 30 days. Mandatory session ID rotation upon authentication and privilege change.                                                       | Server-side session validator middleware.                                              | OWASP Session Mgmt Cheat Sheet                            |
| **SEC-CSRF-001** | CSRF Defense              | All state-changing requests (POST, PUT, PATCH, DELETE) using cookie authentication must validate a cryptographically bound `X-CSRF-Token` header.                                                | Global CSRF validation middleware.                                                     | OWASP CSRF Prevention Cheat Sheet                         |
| **SEC-ELEC-001** | Electron Storage          | Desktop session refresh credentials must be encrypted at rest using Electron `safeStorage` (Windows DPAPI, macOS Keychain, Linux Secret Service). Plaintext token files are strictly prohibited. | Electron main process secure store module.                                             | Electron Security Guidelines<br/>Electron safeStorage API |
| **SEC-ELEC-002** | Electron Isolation        | `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, explicit Content Security Policy (CSP). Preload script only exposes typed `desktopAPI`.                                     | Electron BrowserWindow webPreferences configuration and automated security unit tests. | Electron Security Checklist                               |
| **SEC-RATE-001** | Multi-Layer Rate Limiting | Rate limiting enforced at Reverse Proxy / API Gateway across IP prefix, normalized account identifier, and route class. Progressive delays on failed logins.                                     | Distributed Redis sliding window / token bucket limiter.                               | OWASP Abuse Case Cheat Sheet                              |
