# DiP-Viser Architecture & Component Design

**Experiment Location**: `exp/dip-viser/`  
**Status**: `VERIFIED & OPERATIONAL`  
**Target Model**: Official DiP (Diffusion Planner) Autoregressive Text-to-Motion  
**Visualization Engine**: Viser 1.1.1 (Browser-based WebGL/Three.js)

---

## 1. High-Level System Architecture

The DiP-Viser experiment isolates official DiP inference and interactive 3D motion visualization from all production services (`frontend/`, `backend/`, `infra/`), ARDY experiments, and MotionBricks.

```
+-------------------------------------------------------------------------------+
|                             Client Web Browser                                |
|          (Viser Client: 3D WebGL Canvas + Dynamic GUI Sidebar Controls)       |
+-------------------------------------------------------------------------------+
                                      ▲  HTTP / WebSockets (Port 8080)
                                      ▼
+-------------------------------------------------------------------------------+
|                     Viser Interactive Viewer (app/viewer.py)                  |
|  - Scene graph manager (ground grid, coordinate axes, lights)                 |
|  - Dynamic joint point clouds (/skeleton/joints) & bone lines (/skeleton/bones)|
|  - GUI state bindings (Prompt input, Duration, Guidance, Sliders, Buttons)     |
|  - Continuous animation playback clock (~30-60 Hz daemon loop)                |
+-------------------------------------------------------------------------------+
         ▲                                                │
         │ updates scene handles                          │ submits jobs
         │                                                ▼
+----------------------------------+    +---------------------------------------+
|  Playback Controller             |    |  DiP Model Adapter (app/dip_adapter.py)|
|  (app/playback.py)               |    |  - Subprocess worker execution        |
|  - Precise frame indexing        |    |  - Job state machine                  |
|  - Looping without re-inference  |    |  - Stdout/stderr capture & logging    |
|  - Clamping & speed multiplier   |    |  - Memory & CUDA isolation            |
+----------------------------------+    +---------------------------------------+
         ▲                                                │
         │ binds to clip                                  │ spawns
         │                                                ▼
+----------------------------------+    +---------------------------------------+
|  Motion Decoder & Schema         |    |  Upstream Official DiP Generator      |

|  - Validates 22 SMPL joints      |    |  - DiP checkpoint (model000600343.pt) |
|  - Enforces provenance tagging   |    |  - CLIP text encoder + GloVe          |
+----------------------------------+    +---------------------------------------+
```

## 2. Core Modules and Responsibilities

### 2.1 Configuration (`app/config.py`)
- Pinned paths for checkpoint, upstream repository, output artifacts, prompts and fixtures.
- Kinematic skeleton constants: 22 SMPL joints, official kinematic chains from `paramUtil.t2m_kinematic_chain`, 21 bone segment tuples, parent map with root `-1`.
- Default motion parameters: 20 FPS, 4.0s duration, 7.5 classifier-free guidance scale.

### 2.2 Motion Schema (`app/motion_schema.py`)
- `MotionClip`: Standard dataclass for all motions in the viewer.
- Fields:
  - `schema_version`: `"1.0.0"`
  - `source_model`: Model name (`"DiP"`)
  - `source_checkpoint`: Checkpoint filename
  - `prompt`: Text conditioning string
  - `provenance`: `"real_inference"` vs `"fixture"`
  - `fps`: Native motion rate (20.0 Hz)
  - `num_frames`: Sequence length $T$
  - `duration_seconds`: $T / 20.0$
  - `joint_positions`: `(T, 22, 3)` metric Cartesian float32 array
  - `joint_names`, `joint_parents`, `bones`: Topology specifications
- Strict Validation Rules:
  - Rejects NaN, Inf, empty clips, invalid joint counts ($\neq 22$), non-3D coordinates.
  - Cycle detection and self-parenting verification.
  - Ensures timestamp alignment.

### 2.3 Motion Decoder (`app/motion_decoder.py`)
- `decode_results_npy(source, ...)`:
  - Reads numpy dictionary generated by `sample.generate`.
  - Handles transposition from official `(num_samples, 22, 3, seq_len)` to standard `(seq_len, 22, 3)`.
  - Extracts text prompt and lengths, validates against `MotionClip.validate()`.
- `create_fixture_motion(...)`:
  - Generates deterministic procedural walking skeleton.
  - Exclusively tagged with `provenance="fixture"`.

### 2.4 Model Adapter (`app/dip_adapter.py`)
- Executes DiP generation in an isolated subprocess.
- Benefits:
  - Prevents CUDA memory leaks or out-of-memory errors from crashing the Viser web server.
  - Captures full generation logs to `artifacts/samples/<job_id>/generation.log`.
  - Provides job state transitions: `QUEUED` $\rightarrow$ `RUNNING` $\rightarrow$ `DECODING` $\rightarrow$ `COMPLETED` / `FAILED` / `CANCELLED`.
  - Never blocks the Viser web server event loop.

### 2.5 Playback Controller (`app/playback.py`)
- Continuous time-based clock advancing at arbitrary $\Delta t$.
- Features:
  - Non-destructive looping: looping wraps time within the sequence and never re-runs model inference.
  - Frame clamping: seeking cannot produce out-of-bound errors.
  - Speed scaling: $0.25\times, 0.5\times, 1.0\times, 1.5\times, 2.0\times$.

### 2.6 Viser 3D Viewer (`app/viewer.py`)
- 3D Scene setup:
  - Ground plane on XZ at $Y=0$ with dual-color grid lines.
  - Coordinate axes frame at origin.
  - Up-direction set to $+Y$ (matching HumanML3D coordinates).
- Zero-allocation rendering:
  - `joint_handle.points = current_joints`
  - `bone_handle.points = current_bone_segments`
  - Existing scene handles are updated in-place on each frame tick rather than destroyed and recreated.
- Interactive GUI controls:
  - Dynamic provenance badge (green for real model inference, orange for fixture).
  - Prompt text entry with preset dropdown.
  - Duration and Guidance scale sliders.
  - Compute device selection (GPU cuda:0 vs CPU).
  - Playback buttons (Play/Pause, Seek slider, Loop toggle, Speed, Reset).
  - Display options (visibility, joint size).
  - Collapsible telemetry and diagnostics HUD.

### 2.7 Telemetry & Benchmarking (`app/telemetry.py`, `scripts/benchmark_dip.py`)
- Measures cold start vs warm inference latency.
- Calculates derived metrics:
  - $\text{Generated FPS} = \frac{\text{num\_frames}}{\text{inference\_seconds}}$
  - $\text{Real-Time Factor (RTF)} = \frac{\text{inference\_seconds}}{\text{duration\_seconds}}$
- Differentiates generation latency from viewer playback FPS.
