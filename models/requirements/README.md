# `models/requirements/` — Requirements Models

## Purpose
Maintains machine-readable structured requirements definitions (IDs, functional/non-functional classifications, priority, acceptance criteria, and traceability tags).

## What Belongs Here
- Requirements catalogs in structured YAML/JSON format.
- Traceability matrices linking requirements to test vectors.

## What Must NOT Belong Here
- Narrative prose without structured schema keys.

## Source-of-Truth Relationship
- Canonical source for `docs/02-requirements/`.
